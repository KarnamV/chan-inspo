# Tech notes (Godot 4.7, GDScript, static typing)

Project: `game/`. Main scene `scenes/levels/test_room.tscn` (M1 arena).

## Architecture
- **Fighter** (`scripts/fighters/fighter.gd`, CharacterBody3D): one body type for Jackie and every demon. States: IDLE, ATTACK, DODGE, STAGGER, KNOCKDOWN, GETUP, DEAD, BODY (Sheep possession body), PICKUP, THROW. Data from `FighterData` (.tres): model, size, stats, light combo, heavy, AI attacks.
- **Brain** (`scripts/brains/`): decides what a Fighter does each physics frame. `PlayerBrain` (input), `AIBrain` (nearest hostile, close in, attack on cooldown). **Possession = brain swap** (+ team swap). Monkey/Tiger twin reuse this later.
- **PlayerController** (`scripts/player/`): owns non-body player state: spirit meter, talismans (M1: Sheep on slot 1), which Fighter is controlled, camera target.
- **Props** (`scripts/props/`): RigidBody3D + `PropData` (.tres). FREE → HELD (BoneAttachment3D on `RightHand`) → swung (wear) / THROWN (damages on contact) → BROKEN → spawns `data.pieces`.
- **Combat**: `Hitbox` (Area3D, polls overlaps, hits each hurtbox once per activation), `Hurtbox` → `Fighter.receive_hit`, `Health` (physical/magic resists, shatter strips physical armor), `DamageInfo` payload.
- **Autoloads**: `Inputs` (all bindings in code), `Events` (signal bus), `Juice` (hitstop, camera shake).
- **Level root**: loose props/pieces parent to the node in group `level_root` (Arena), not `current_scene`.

## Talismans, boons, run
- `scripts/talismans/zodiac.gd`: all 12 (`Zodiac.make(id)`), base `Talisman` (equip/unequip/activate/tick/on_controlled_changed/on_room_cleared). PlayerController holds `equipped` (3) + `boons`.
- `scripts/fighters/boss_kit.gd`: boss signature moves used by both `BossBrain` and the player's Monkey form (light = melee, heavy = ground pound, grab = meat hook, chi_mod + button = specials).
- `scripts/run/`: `meta.gd` (autoload Meta, user://meta.json), `run_state.gd` (autoload Run, realm 1 room list, doors, waves), `rewards.gd` (offers: talisman/boon/draft/gold, shop, shrine), `boons.gd` (12 boons; one-time effects in `apply_once`, behaviour hooks re-equipped per room), `run_room.gd` (RunRoom extends Arena), `door.gd`, `npc.gd`, `hub.gd`.
- UI: `ChoicePanel` (modal pick-one, pauses tree), `DialoguePanel`, `Hud`, `BossBar`.
- Main scene: `scenes/run/hub.tscn`. Test scenes: `scenes/levels/test_room.tscn` (M1), `combat_arena.tscn` (M2 waves). Test keys in arenas: 1-0,-,= swap talismans.

## Look, UI, input
- Floors/walls: `assets/shaders/flagstone.gdshader`, `lacquer_wall.gdshader` (world space). Street + buildings: `Arena._build_street()`. Effects: `scripts/core/vfx.gd` (static; CPU particles for one-shots).
- Character meshes render on layer 2; blob-shadow decals cull to layer 1 so they don't paint bodies.
- UI theme: `assets/ui/theme.tres` set in project settings; rebuild with `godot --headless --path . -s tools/build_theme.gd`. Type variations `Header`, `Title` (Lilita One).
- Input prompts: never hard-code keys; use `Inputs.label(action)` / `Inputs.combo(mod, action)`.
- Main scene `scenes/run/intro.tscn` → forwards to hub once `Meta.seen` has `intro`. Captures that open intro/hub write the real save: back up `%APPDATA%/Godot/app_userdata/Demon Realm Escape/meta.json` first.
- Don't use `clip_children` (scene-change engine error in 4.7).

## Data
`game/tools/build_data.gd` generates `data/fighters/*.tres`, `data/props/*.tres` once (ResourceSaver). After that, tune the .tres in the Inspector. Re-running overwrites.

## Assets
- Generated by the ai-gamedev-pipeline skill: `assets/manifest.csv` + `asset_runner.py` → `art/<cat>/<id>/`.
- `tools/sync_assets.py` copies deliverables into `game/assets/` (Godot only loads res://).
- Clip names in Godot = manifest preset names with `-loop` stripped: idle, walk, run, sprint, punch_jab, punch_cross, swing, dodge, hit, hit_head, death, pickup, crouch, chi_cast, chi_enter, jump_start, jump_land, guard + procedural heavy, throw. `AnimDriver` falls back (knockdown/getup = death forwards/backwards).

## Gotchas found
- Add a body to the tree only **after** setting its position (`f.position = at; add_child(f)`). Spawning at the origin first makes bodies overlap and physics pops one on top of the other.
- GUT command line has no `current_scene`; tests use a `level_root` Node3D.
- `-s` SceneTree scripts compile before autoloads exist, so any script touching `Events`/`Juice` fails. Bot tests are **scenes** (`tests/bot/*.tscn`), run with `godot --headless --path . res://tests/bot/bot_m1.tscn`.

## Checks
- Unit: `godot --headless --path . -s addons/gut/gut_cmdln.gd -gexit`
- Boot: `godot --headless --path . --quit-after 300`
- Bots (exit 0 = pass): `bot_m1` (core loop), `bot_m2` (6 demon types), `bot_m3` (12 talismans), `bot_run` (full realm-1 run). Run with `--fixed-fps 60`. Bots that drive UI must set `process_mode = ALWAYS` (panels pause the tree).
- Balance probe: `bot_run.tscn -- --fair` = real HP/damage, no-dodge bot; prints `FAIR: rooms reached N`.
- Physics interpolation is on: move nodes in `_physics_process`; anything moved in `_process` (camera, shockwave) sets `physics_interpolation_mode = OFF`. Follow bodies via `get_global_transform_interpolated()`.
- Visual: Movie Maker capture (`--write-movie movie/f.png --fixed-fps 24`).
